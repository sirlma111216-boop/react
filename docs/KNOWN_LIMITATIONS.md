# 알려진 한계와 범위 결정

## 제품 범위 결정 (미완성이 아님)
- **팀 간 직접 거래·실시간 흥정 없음.** 경쟁은 시장 선택·경로 최적화·공개 입찰로만 발생합니다.
- **장문 채팅 없음.** 교실에서 모여 대화하는 것을 기본으로 하며 핑·인계 메모만 제공합니다.
- **개인 순위·성적표 없음.** 배지는 연출용이며 돈이나 점수로 연결되지 않습니다.
- **식음료 메뉴 없음.** product recipe 타입은 계약 묶음(C07)에만 사용합니다.

## 검증하지 않은 것
- **인간 플레이테스트.** 봇 지표(공정성·진행 가능성·다양성)는 사람의 재미를 보증하지 않습니다.
- **실제 30대 기기의 네트워크 성능 측정.** 로컬 workerd 에서 30학생+교사 통합 테스트(명령 p95 수십 ms 수준)는 통과했지만, 학교 무선망 RTT 는 측정하지 않았습니다.
- **오디오.** 파일 미제작 상태이며 무음 fallback 으로 동작합니다. 파일을 넣고 manifest `status: "ok"` 로 바꾸면 재생됩니다. Opus/MP3 인코딩·루프 지점 검증은 파일이 생긴 뒤 합니다.
- **미디어 라이선스.** 이미지 19장의 생성 서비스 이용권·배포 범위는 사용자가 확인해야 하며 manifest 에 `unverified` 로 표시했습니다.

## 기술적 한계
- **세션 토큰은 localStorage** 에 저장합니다(HttpOnly 쿠키 아님). 같은 origin 의 다른 스크립트가 없으므로 XSS 방어는 React 의 이스케이프에 의존합니다. 닉네임·팀 이름은 서버에서 태그 문자를 제거합니다. 기기 변경 시 교사 API(`/recover`)로 토큰을 재발급할 수 있으나 UI 버튼은 없습니다(교사가 내보내기 후 재입장 안내).
- **교사 인증**은 단일 계정(`teacher`)과 비밀번호에서 파생한 HMAC 키입니다. 비밀번호를 바꾸면 이전 키가 무효화됩니다. 로그인 시도 제한은 Cloudflare 의 기본 보호에 의존합니다.
- **WebSocket 은 원격 분석·외부 SDK 를 쓰지 않으며** 서버 로그도 방 코드·명령 종류만 남깁니다(닉네임·토큰은 로그에 남기지 않음).
- **타이머**: V2부터 새 방은 수동 진행이며 알람은 방 정리에만 쓰입니다. 구버전 시간제 방에서만 deadline 알람이 단계를 진행합니다(늦은 알람은 누락된 경계를 순서대로 최대 6단계 처리).
- **관측 기록**은 방마다 최근 600건만 보존하며 개인 식별은 playerId 수준입니다. 교사 내보내기에는 팀 단위 요약만 담습니다.
- **스키마 마이그레이션**: 방 상태는 `meta/players/teams/game:core/game:team:*` 키로 저장됩니다. 필드를 추가할 때는 기본값을 코드에서 보완하고, 호환되지 않는 변경은 `ENGINE_BUILD`/`SCIENCE_VERSION` 을 올린 뒤 진행 중 방이 없을 때(수업 시간 밖) 배포합니다. 진행 중 방의 규칙은 hot reload 로 바뀌지 않습니다.
- **DO 값 크기**: 팀 상태를 팀별 키로 분리했고 로그는 400건으로 제한합니다. 8팀×8명 경기에서도 키당 128KiB 를 넘지 않도록 설계했지만 극단적 재고 분할(수백 로트)은 테스트하지 않았습니다.
- **Preview 배포**: Durable Object 가 포함된 Worker 의 PR preview 는 실시간 방 검증에 적합하지 않으므로 staging 환경(`--env staging`)을 사용합니다.

## 밸런스 관련
- `reports/balance/BALANCE_REPORT.md` 참조. 시작 묶음 간 평균 자산 차이는 봇 정책과 상호작용하며, 봇은 사람의 전략을 대표하지 않습니다.
- 설비 투자 봇은 의도적으로 보수적 ROI 규칙을 쓰며, 사람이 더 잘 투자할 여지가 있습니다.

- 키보드 조작·포커스 표시·reduced motion·색+문양 병행·소리 없이 진행을 지원합니다. 스크린리더용 반응식 읽기(`aria-label`)는 기본 제공하지만 전문 검수는 하지 않았습니다.
