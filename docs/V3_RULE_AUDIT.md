# V3 규칙 감사 — 점수·정산·재고·상점·출하·이벤트 보상

2026-09-27. 개정(V3) 전에 실제 코드(`src/shared/engine/*`, `src/shared/config/economy.ts`, `src/worker/room.ts`)를 읽어 확인한 현재 동작과, V3 에서 바꾼 점을 적는다. 기획 문서가 아니라 코드가 근거다. 파일·함수 이름은 감사 시점 기준이다.

### 감사 중 발견해 고친 것

1. **납품 가능 판정 중복** — 엔진·UI·봇이 `grade !== 'purchased'` 를 각자 검사. 지원품 등급이 생기면 서로 어긋날 수 있어 `engine/commands.ts` `lotUsableFor` 로 통합하고 UI(출하장·의뢰 보드·코치)·봇이 모두 이 함수를 쓴다.
2. **클라이언트 만들기 가능 판정이 설정을 무시** — 작업 자리 2개를 코드에 고정, 원료 대체 상태를 첫 항목 이름으로 표시(예: 클래식에서 "염화칼슘 수용액"). V3 작업 카드는 서버와 같은 `pickReactantLots` 로 부족량을 계산하고, 슬롯 수는 설정값(`reactionSlots`)을 쓰며, 원료 이름은 가진 것 → 상점에 있는 것 순으로 표시한다(`client/lib/slot.ts`).
3. **R01 카드 제목 "물 만들기"가 실제 생성물(수증기)과 불일치** → "수증기 만들기". 반응식·계수는 그대로.
4. **쓰이지 않는 옛 컴포넌트** — `ContractCard`, `ShopModal/EquipmentModal`, `LotChip`, 색 네모 `Tokens`(임시 기하 도형 재고 표시)가 남아 있었다. 제거.
5. **장소 화면 모달이 HUD 아래에 깔림** — 장소 전환 애니메이션(transform)이 쌓임 맥락을 만들었다. 모달을 `document.body` 로 그린다.
6. `TeamState.cancelledThisRound` 는 쓰이지 않는 필드(기록만). 저장 호환을 위해 남긴다.

### 경제 가치 원장 (물질량 원장과 별개)

- 로트마다 `basis`(밀리코인 정수) = 회수 원가 풀. 들어오는 곳은 **구매(실제 지불액, 할인 반영)** 와 **지원품·구버전 시작 묶음(명시된 외부지원 가치 = 기준 가치 × 칸)** 뿐.
- 반응: 투입 로트에서 뗀 풀을 산출 로트들에 기준 가치 비중으로 **나눠 준다**(정수 분배, 나머지는 큰 쪽). 부산물마다 같은 원가를 복제하지 않는다. 공정 용수·에너지·수수료·촉매는 풀을 늘리지 않는다.
- 가공: 로트 풀 전체를 산출에 나눈다. 병합은 합, 분할은 비례(마지막 칸이 나머지 전부).
- 나가는 곳: 납품(`delivered`), 매입(`sold`). 불변식 `inflow = 보유 풀 + delivered + sold` 를 `verifyValueLedger` 가 검사하고 시뮬레이터가 매 정산마다 확인한다(2,000경기 이상에서 불일치 0).
- 기준 회수가치(`materialValues`)는 가격표와 반응 골격에서 유도(`config/values.ts`)해 **경기 시작 시 설정 스냅숏에 고정**한다.

### 계약의 지원품 허용 조건

`ContractRequirement.allowSupport` 를 명시한 조건에만 지원품 완성 소재를 보탤 수 있다. 명시하지 않으면 불가(구매 물질 납품 금지는 그대로). C01~C13 은 허용, **C14(아세트산에틸 1칸)는 불허** — 1칸짜리 조건이라 지원품 1칸이 계약 전체를 무료로 끝낼 수 있기 때문. 완성 소재 풀에서도 1칸 조건 물질과 `NH4Cl_s`·`ethylAcetate_l` 은 제외한다(`support.finishedExclude`).

### 수동 라운드·권한

- 라운드마다 팀별 `support: SupportGrant`(pending/received/forfeited, grantId `S{라운드}-{팀}`, 공통 예산). 다음 담당자는 라운드 시작에 이미 정해져 있고 그 담당자만 확정한다(서버의 담당자 검사). 팀원은 같은 묶음을 보고 `support:<grantId>:<i>` 핑으로 반송을 제안한다.
- 자기 팀 지원품 전에는 사기·에너지·만들기·정리·배달·설비·입찰·매입·준비 완료를 잠근다. 장소 이동·의뢰 확인·주문 받기·메모·핑은 가능. 다른 팀을 기다리는 학급 전체 장벽은 없다.
- 교사 "이번 라운드 건너뛰기"와 라운드 마무리 시 미선택 지원품은 **수령 포기**로 기록(몰래 추첨하지 않음). 교사 대리 선택은 `resolvedBy: 'teacher'` 로 기록.
- 새로고침·재접속·기기 변경으로 내용이 바뀌지 않는다: (시드, 라운드, 팀)으로 만들고 저장, 확정은 grantId 1회.
