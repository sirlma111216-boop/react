# UX 개정 V3 — 물질 아트 · 작업 카드 · 의뢰 보드 · 연구지원품 · 재고 매입

2026-09-27. V2 의 4개 장소·수동 라운드·팀 협업은 그대로 두고, 첨부 화면에서 지적된 네 문제를 **정보를 줄이지 않고** 일러스트 통일·읽는 순서·카드 폭·명확한 상태·의뢰와 행동의 연결로 풀었다. 규칙 변경은 [V3_RULE_AUDIT.md](V3_RULE_AUDIT.md).

## 1. 물질 그림 (모든 화면 공통)

- 공통 컴포넌트 `client/components/Art.tsx`: `MaterialArt`(순물질, materialId 기준) · `MixtureArt`(혼합물 베이스 + 성분 아이콘 최대 3개) · `ObjectArt`(지원품 상자·회수 상자·촉매 카트리지·효모).
- 쓰는 곳: 상점(구입·매입), 재료 선반, 작업 카드(재료·결과·헤더), 가동 중 작업 자리, 완성품 트레이, 의뢰소 주문 조건, 의뢰 보드, 출하대, 지원품 상자, 회수 상자, 결과 화면 잔여 재고, 창고 상세, 도감, 검수 화면. 같은 물질은 원료든 생성물이든 같은 그림.
- 상점의 🫧🧱🧪 이모지, 공방의 SVG 병·상자, 출하장의 📦/▢, 색 네모 재고 토큰을 모두 걷어 냈다(이미지가 없을 때만 점선 임시 대체 + 이름).
- 물과 수증기, 염산 수용액과 염화수소 기체는 다른 그림. 한 그림을 여러 상태가 쓰면 상태 배지(수용액·결정·고체·발효액·정제)를 붙인다. 이름·화학식·수량·상태·품질은 코드가 쓴다. 그림 속 알갱이 수는 수량이 아니다(창고 상세·도감에 안내문).
- 크기 변형: 64px 이하 표시에는 128px, 그 이상은 256px, 큰 오브젝트는 512px 파일만 받는다(`srcset`, `loading=lazy`). 48장 합계 약 1.2MB, 원본 1024px 파일은 앱이 읽지 않는다.

## 2. 작업 카드 6영역 (`WorkCard.tsx`)

1. **헤더**: 생산물 그림 56px + 제목 21px(실제 생성물과 일치, R01 "수증기 만들기") + 상태 글자(✓ 바로 가능 / ! 재료 부족 / ⟳ 가동 중·자리 없음 / · 다른 사람 차례). 부제는 선택한 의뢰와의 관계("냉각 장치용 깨끗한 물 · 응축 전 단계", "다음 단계 재료(산소)").
2. **재료 → 결과**: 그림 52px + 이름 + ×수량(17px). 재료 칸(아이보리)과 결과 칸(옅은 청록)을 나누고 화살표를 둔다. 부족한 재료만 빨간 테두리와 "N개 부족". 섞여 나오는 결과는 혼합물 그림 + "◆ 정리 필요"(오류색 아님).
3. **반응식 줄**: 독립된 밝은 면, 18px, `<sub>` 아래첨자·계수·상태기호. 계수나 화학식 중간이 아니라 +/화살표에서만 줄을 바꾼다.
4. **비용 줄**: 아이콘 + 이름 + 값 — "에너지 1 · 행동력 1 · 정산 1회 뒤 완성"(툴팁: 실제 초가 아니라 라운드 마무리 횟수). 촉매·공정 보조물 칩(그림 포함), 일부만 반응, 완성 뒤 정리 1번.
5. **가능 여부**: 서버와 같은 `pickReactantLots` 로 계산한 실제 원인 — "탄산나트륨 1개가 부족해요", "전해 모듈이(가) 필요해요", "빈 반응기가 필요해요", "에너지 2가 더 필요해요", "먼저 이번 라운드 연구지원품을 고르세요", "이번 조작: ○○".
6. **행동**: 반응 시작(+두 배로) / 부족한 재료 보기(상점 추천으로) / 설비 확인 / 추가 반응기 보기 / 에너지 충전하러 가기 / 👍 팀원에게 추천. 회색 비활성 버튼 하나로 끝내지 않는다. 최종 실행은 담당자만(서버 검증).

배치: 카드 최소 폭 420px, 넓으면 2열, 좁으면 1열(`minmax(min(100%, 420px), 1fr)`). 카드 폭이 400px 이하가 되면(컨테이너 질의) 재료→결과를 세로로 쌓고 화살표를 아래로 돌린다. 버튼 줄은 카드 아래에 맞춘다(`margin-top:auto`). 긴 한글 이름은 글자 단위가 아니라 낱말 단위로 줄바꿈(`keep-all`).

## 3. 작업대 위 의뢰 보드 (`MissionBoard.tsx`)

- 공방 맨 위에 항상 있다(휴대전화에서도 접히지 않음). 의뢰 보드 그림(`obj-mission-board`)을 `border-image` 로 써서 모서리 클립은 그대로, 가운데 종이만 늘어난다. 받은 의뢰가 없으면 "의뢰소에서 받기" 안내.
- 의뢰 2개까지 나란히, 집중 의뢰는 호박색 강조. 3개 이상이면 탭 + 선택 의뢰.
- 성분마다: 그림 + 이름 + "준비됨 N / 필요 M" + 막대(준비됨 청록 · 정리 필요 호박 · 작업 중 빗금) + "◆ 정리 필요 2(응축하기)", "⟳ 작업 중 1(정산 뒤)", "아직 필요 1", "지원품 1 포함", "다른 의뢰(○○)와 공용", 추천 경로 + "다른 방법 ▸".
- 계산은 `engine/mission.ts`(서버 상태만 읽는 순수 함수): 작업 중 산출은 준비됨에 더하지 않고, 혼합물·수증기는 출하 가능으로 세지 않으며, 같은 재고는 집중 의뢰부터 가상 배정(실제 예약 아님)하고 겹치면 공용 표시.
- 카드 제목을 누르면 검증된 반응·가공 그래프로 판정한 **직접 목표**(진한 테두리 + "선택한 카드가 만드는 목표")와 **다음 단계 재료**(점선 + 그림 + 이름, 최대 3단계 상류)를 표시. 원소가 같다는 이유만으로는 표시하지 않는다.
- 서버 상태가 바뀐 성분만 0.9초 반짝(움직임 줄이기 설정이면 없음). 공방 전체가 번쩍이거나 화면이 바뀌지 않는다. 출하 가능해지면 "출하장으로 →".

## 4. 연구지원품 (`SupportPanel.tsx`)

- 라운드가 열리면 공방 탭에 "지원품" 배지와 💡 안내. 다른 장소를 보는 학생 화면을 강제로 바꾸지 않는다.
- 공방의 큰 배송 트레이(닫힌 상자 3개) → "지원품 확인" → 0.7초 여는 연출(눌러서 건너뛰기, 움직임 줄이기 시 없음) → 세 묶음 전체를 동시에 보여 주고 반송할 1묶음을 고르면 반송 상자 그림 + "반송" 표시 → "선택한 1묶음 반송 · 나머지 받기". 받을 물량을 확정 전에 한 줄로 보여 준다.
- 담당자가 아니면 "이 상자 반송 제안" 핑, 담당자 화면에 제안 수가 보인다.
- 교사 보드: "지원품 선택 대기" 표시, "지원품 대신 고르기"(기록됨) 또는 "이번 라운드 수령 포기로 진행".

## 5. 상점 재고 매입

- 상점 한 공간에서 "구입 / 재고 매입" 전환(새 장소·표 추가 없음). 매입 목록에는 넘길 수 있는 자기 순물질만, 받은 의뢰에 필요한 재료는 호박색으로 "받은 의뢰에 필요 · N개".
- 회수 상자(`obj-recycling-crate`) 옆에 실제 견적: 줄별 회수가(소수), 합계(내림), 라운드 한도·경기 남은 한도·이번 라운드 남은 횟수, "넘기면 ○○ N개가 부족해져요(그래도 넘길 수 있어요)". 한도를 넘는 칸은 담기지 않는다. 0코인이면 넘기지 않도록 안내. 확정 명령에 화면 견적을 함께 보내고 서버 견적과 다르면 거절.

## 6. 확인 (2026-09-27, 로컬 workerd + 브라우저)

- 1366×768: 공방(의뢰 보드·지원품 트레이·작업대·선반·트레이가 한 화면), 작업 카드 창(2열, 미니 의뢰 보드 고정), 지원품 선택 창, 상점 재고 매입 — 화면 캡처로 확인.
- 375×812: 가로 넘침 없음(scrollWidth = 뷰포트), 의뢰 보드 펼침, 작업 카드 1열·세로 흐름.
- 움직임 줄이기: 반짝·여는 연출 애니메이션 끔(CSS).
- 키보드: 카드 헤더·반송 선택·확정·스테퍼가 모두 `<button>`(포커스 표시 공통).

## 남은 사람 플레이테스트 항목

- 작업 카드에서 "재료 → 결과 → 반응식" 순서로 실제로 읽히는지, 카드 제목 누르기(보드 강조)를 발견하는지.
- 지원품 반송 선택이 고민을 만드는지(완성 소재 1칸 vs 기초 원료 8~10칸), 팀원 반송 제안이 쓰이는지.
- 재고 매입이 "막판 정리" 이상으로 쓰이는지, 한도 안내가 이해되는지.
